## 🎯 Objective

## 💻 The Work

### 🔴 MUST DO — SQL retrieval (25 min)

Closed book, 4 minutes each. **No reference, no autocomplete.**

1. Top 3 per group with a window function
2. Period-on-period change with `LAG`
3. A running total with an explicit frame
4. A cohort month index from a first-purchase date
5. `NTILE(5)` scoring, with the ordering correct
6. Conditional aggregation as a pivot

**Score: ___ / 6.** These six are Project 2, and they are also the six most common SQL interview patterns.

### 🔴 MUST DO — the Project 2 decision (25 min)

**Ships tomorrow.** You have Day 64 — about 75 minutes.

| | Honest answer |
|:--|:--|
| Database built, schema documented | ☐ |
| At least two questions answered with numbers | ☐ |
| Every query readable and commented | ☐ |
| The at-risk / funnel business case quantified | ☐ |
| `NOTES.md` readable by someone who has not seen the data | ☐ |

**If more than two are unticked, cut to two questions today.** Day 64 is for the recommendation memo and the README — **not** for new analysis. A project with two solid findings and a good memo beats one with three findings and no write-up, because the write-up is what a reviewer reads.

### 🔴 MUST DO — the hackathon note (10 min)

If you have not written it: what you built, what you contributed, **what you could not do.** Ten minutes, and it becomes an interview answer and an honest skill-gap list.

## 🔬 Understanding Check

1. **Integration.** Describe the whole Project 2 path: raw CSVs → database → cohort table → finding → recommendation. Name the technique at each step.
2. **Reasoning.** Which of the six SQL patterns is least automatic? What will you do about it before Day 89's interview drills?
3. **Judgement.** Is Project 2 on track, or did you cut it? What did you cut?
4. **Gap.** From the hackathon — what could you not do? Is it something these ninety days cover, or something for 2027?
