### 21. Constructor in Python

### 22. In-depth Attribute and Method

- **Instance Attribute**: Created using `self`, e.g., `self.name`.
- **Class Attribute**: Created inside the class without `self`.
- **Instance Method**: Uses `self` to operate on instance data.
- **Class Method**: Uses `@classmethod` and operates on class-level data.
- **Static Method**: Defined with `@staticmethod`, does not rely on `self` or `cls`.

**Key Concepts**: Differentiates instance attributes and methods from class-level and static methods in terms of how they interact with data.

### 23. Inheritance

- **Inheritance**: A mechanism where a child class can inherit properties and methods from a parent class.
- **Types**:
    - **Single-Level**: One class inherits from another. (`Parent class ==> Child class`)
    - **Multilevel**: A class inherits from another class that is already a child. (`Parent class ==> Child class ==> Child class`)
    - **Multiple**: A class inherits from more than one parent class. (`Parent class1 ==> Child class`, `Parent class2 ==> Child class`)
    - **Hierarchical**: Multiple classes inherit from a single parent class. (`Parent class ==> Child class1`, `Parent class ==> Child class2`)

**Key Concepts**: Inheritance allows classes to reuse and extend functionality from other classes, enabling the creation of more complex structures through parent-child relationships.

### 24. Encapsulation

- **Encapsulation**: Bundling data (attributes) and methods into one unit (class), while controlling access to the attributes using access modifiers.
- **Access Modifiers**:
    - **Public**: Accessible anywhere.`public attribute/method`
    - **Protected**: Accessible in the class and subclasses. The protected access modifier in Python doesn't function as strictly as in some other languages like Java or C++.`protected attribute/method`
    - **Private**: Accessible only in the class. We use `__` (double underscore) to define private attributes and methods, meaning they are not accessible outside the class or even in child classes.`__private attribute/method`

**Key Concepts**: Encapsulation allows the grouping of data and methods into a single unit (class) and the protection of the data by controlling access to it via access modifiers.

### 25. Abstraction

- **Abstraction**: Hides complex details, exposing only essential features.
- **Abstract Class**: Contains one or more abstract methods. `class AbstractClass:`
- **Abstract Method**: A method not implemented in the abstract class. Subclasses must implement it. `@abstractmethod def abstract_method(self):`
- **abc Module**: Used to define abstract classes and methods. `from abc import ABC, abstractmethod`

**Key Concepts**: Focuses on what an object does, not how it does it.

### 26. Polymorphism

- **Polymorphism**: Allows methods with the same name to have different behaviors in different classes, often achieved via `method overriding`.
- **Types**:
    - **Method Overloading**: Simulated in Python using `default` or `variable-length` arguments.
    - **Method Overriding**: Subclass method replaces the `superclass` method.

**Key Concepts**: Polymorphism enables one interface for multiple data types via `method overloading` and `method overriding`.

### 27. Dunder/Magic Methods

- **Dunder Methods**: Special methods in Python that define object behavior for built-in operations, prefixed with double underscores (e.g., `__init__`, `__str__`).
- **Common Dunder Methods**:
    - `__init__(self, ...)`: Constructor, called when an object is created.
    - `__add__(self, other)`: Defines behavior for the `+` operator.
    - `__eq__(self, other)`: Defines behavior for the `==` operator.
    - `__getitem__(self, key)`: Allows indexing like lists and dictionaries.
    - `__str__(self)`: Provides string representation of an object.
    - `__len__(self)`: Returns the length of an object, used by `len()`.

**Key Concepts**: Dunder methods allow you to customize built-in operations for objects, providing a way to define how objects behave in various situations, such as addition, comparison, and representation.

### 28. Modules and Packages

- **Module**: A file containing Python code (functions, variables, classes) that allows code reuse and organization.
- **Package**: A directory of modules with an `__init__.py` file, enabling hierarchy.

**Creating and Using Modules**:

- **Creating a Module**: A Python file (`.py`) with functions or variables.
- **Using a Module**: Use `import module_name` or `from module_name import ...` to access its contents.

**Creating and Using Packages**:

- **Creating a Package**: A directory with an `__init__.py` file and multiple module files.
- **Using a Package**: Use `import package_name.module_name` to access modules within the package.

**Key Concepts**: Modules help organize code, while packages allow for hierarchical organization of modules.

### 3. Data Distribution

- **Introduction**: Understanding how data is spread and its patterns.
- **Measures of Variability**:
    - `Mean`: The average of data.
    - `Variance`: Measures dispersion from the `Mean`. Formula: `Σ(x - Mean)² / N`
    - `Standard Deviation (SD)`: Square root of variance. Formula: `√Variance`
- **Frequency & Density Representation**:
    - `Histogram`: Bar graph showing frequency distribution.
    - `Frequency Polygon`: Line graph linking histogram midpoints.
    - `Density Curve`: Smooth curve approximating data distribution.
    - Making the Density curve using these things Histogram —> Frequency polygon —> Density curve
- **Types of Distributions**:
    - `Symmetrical`: Balanced around the center. Mean, median, mode at same position.
    - `Right-Skewed`: Tail extends to Right side of data.
    - `Left-Skewed`: Tail extends to left side of the data.
- **Outliers**: Extreme values that distort analysis.
- **Normal Distribution**:
    - Bell-shaped, symmetrical curve centered around `Mean`.
    - `68%-95%-99.7% Rule`: % of data within `1-2-3 SD`.
    - `Z-Score`: Standardizes a value. Formula: `(X - Mean) / SD`
- **Covariance & Correlation**:
- `Covariance`: Measures directional relationship between variables.
- `Correlation (r)`: Scaled `Covariance`, ranges `1 to 1`.
- Formula: `Cov(X, Y) / (SDx * SDy)`

**Key Takeaways**: Understand distribution shapes, variability, and relationships between variables.

### 4.  Probability

- **Introduction to Probability**:
    - Measures the likelihood of an event occurring.
    - Formula: `P(Event) = Favorable Outcomes / Total Outcomes`.
- **Simple Probability**:
    - Probability of a single event happening.
    - Example: Rolling a die, `P(rolling a 3) = 1/6`.
- **Addition Rule & Union vs Intersection**:
    - `Union (A ∪ B)`: Either event `A` or `B` (or both) occur.
    - `Intersection (A ∩ B)`: Both events `A` and `B` occur simultaneously.
    - **Formula**: `P(A ∪ B) = P(A) + P(B) - P(A ∩ B)`.
- **Independent & Dependent Events, Conditional Probability**:
    - `Independent`: One event does not affect the other.
    - `Dependent`: The outcome of one event influences the other.
    - `Conditional Probability`: Probability of `A` given `B` happened:
        - `P(A|B) = P(A ∩ B) / P(B)`.
- **Bayes' Theorem**:
    - Calculates `P(A|B)` when reverse probabilities are known.
    - **Formula**: `P(A|B) = [P(B|A) * P(A)] / P(B)`.

**Key Takeaways**: Understanding probability rules, dependencies, and Bayes' Theorem helps in real-world decision-making and data science applications.

### 5. Hypothesis Testing

- **Introduction to Hypothesis Testing**:
    - A statistical method to make inferences about a population using sample data.
    - Helps decide whether to accept or reject a **claim (hypothesis)**.
- **Types of Hypotheses**:
    - **Null Hypothesis (H₀)**: Assumes no effect or no difference exists.
    - **Alternative Hypothesis (H₁)**: Assumes a significant effect or difference exists.
- **Steps in Hypothesis Testing**:
    1. Define **H₀** and **H₁**.
    2. Set the **significance level (α)**, commonly 0.05.
    3. Choose the **test statistic** (Z, t, χ², ANOVA).
    4. Compute the test statistic from sample data.
    5. Compare with the **critical value** or **p-value**.
    6. **Reject H₀** if p-value < α; otherwise, **fail to reject H₀**.
- **Z-Test**:
    - Used when population variance is known or sample size > 30.
    - Formula: `Z = (X̄ - μ) / (σ / √n)`
- **T-Test**:
    - Used when population variance is unknown and sample size < 30.
    - Types:
        - **One-sample t-test** — compares sample mean to population mean.
        - **Independent two-sample t-test** — compares means of two groups.
        - **Paired t-test** — compares means from the same group at different times.
- **Chi-Square (χ²) Test**:
    - Used for **categorical data** to test independence or goodness of fit.
    - Formula: `χ² = Σ [(O - E)² / E]`,
        
        where *O* = Observed value, *E* = Expected value.
        
- **ANOVA (Analysis of Variance)**:
    - Used to compare **means of three or more groups**.
    - Tests if at least one group mean differs significantly from others.
    - Based on **F-statistic**:
        
        `F = Variance between groups / Variance within groups`.
        

**Key Takeaways**: Hypothesis testing validates assumptions using statistical evidence. Z and T tests handle mean comparisons, Chi-Square tests categorical relationships, and ANOVA compares multiple group means.

## **Machine Learning Overview**

- **Definition:** Learning from `data` to make predictions.

    - `Supervised Learning` → Labeled data
    - `Unsupervised Learning` → Unlabeled data
    - `Reinforcement Learning` → Learn by `trial & error`

## **Supervised Learning – Regression**

### **Linear Regression**

- Predicts **continuous values**
- Equation: `Y = mX + c`
- **Goal:** Minimize error between actual & predicted
- **Assumptions:** Linearity, No multicollinearity, Normality, Homoscedasticity
- **Regularization:** `Ridge (L2)`, `Lasso (L1)`
- **Metrics:** `MSE`, `RMSE`, `R² Score`
- **Implementation:** `LinearRegression()` from `sklearn`

### **Polynomial Regression**

- Extends linear regression to fit **curves**
- Uses `PolynomialFeatures` to add higher-degree terms

---

## **Supervised Learning – Classification**

### **Logistic Regression**

- For **binary classification**
- Uses `sigmoid function` → outputs probability between `0` and `1`
- **Threshold:** >0.5 → `Class 1`, else `Class 0`
- **Metrics:** `Confusion Matrix`, `Accuracy`, `Precision`, `Recall`, `F1-Score`, `ROC-AUC`

### **K-Nearest Neighbors (KNN)**

- Classifies based on **majority of nearest neighbors**
- Uses distance metrics like `Euclidean` or `Manhattan`
- **Hyperparameter:** `K` (no. of neighbors)

### **Decision Tree**

- Splits data based on conditions
- Uses `Gini` or `Entropy` to find best split
- **Pruning** helps avoid overfitting

### **Random Forest**

- Collection of multiple `Decision Trees`
- **Final Prediction:** Majority vote or average
- **Pros:** Handles overfitting better than single tree

### **Support Vector Machine (SVM)**

- Finds best `hyperplane` to separate classes
- Uses `kernel trick` (`linear`, `rbf`, `poly`) for non-linear data

### **Naive Bayes**

- Based on `Bayes' Theorem`
- Assumes **independent features**
- Types: `GaussianNB`, `MultinomialNB`, `BernoulliNB`
- Common in `text classification`, `spam detection`

---

## **Classification Metrics**

- `Confusion Matrix`
- `Accuracy` = (TP + TN) / Total
- `Precision` = TP / (TP + FP)
- `Recall` = TP / (TP + FN)
- `F1-Score` = 2 × (Precision × Recall) / (Precision + Recall)
- `ROC-AUC` → Measures model’s discrimination ability

---

## **Unsupervised Learning**

### **K-Means Clustering**

- Groups data into `K` clusters
- Minimizes distance between points & cluster centers

### **Hierarchical Clustering**

- Builds tree-like structure (`dendrogram`)
- Shows relationships between clusters

### **DBSCAN**

- Groups points based on **density**
- Detects noise & irregular shapes

### **PCA (Principal Component Analysis)**

- Reduces dimensions while retaining variance
- Used for `visualization` and `speed improvement`

---

## **Model Evaluation & Tuning**

- `Train-Test Split` → Evaluate on unseen data
- `Cross Validation` → Better performance estimation
- `GridSearchCV`, `RandomizedSearchCV` → Tune hyperparameters
- `Bias-Variance Tradeoff` → Balance underfitting & overfitting
- `Underfitting` → Too simple model
- `Overfitting` → Too complex model

# Phase 11 : Generative AI Revolution

## **Introduction**

- `Generative AI` → Models that **create** new content (text, image, code, audio, etc.)
- Examples → `ChatGPT`, `Gemini`, `Claude`, `DALL·E`, `Midjourney`
- Core Idea → Learn data patterns → **generate similar outputs**
- Works using → `Large Language Models (LLMs)` and `Diffusion Models`

---

## **Large Language Models (LLMs)**

- Trained on massive text data
- Predict the next word/token in a sequence
- Examples → `GPT`, `Gemini`, `Claude`, `Mistral`
- **Key Concepts:**
    - `Tokenization` → Convert words into numerical form
    - `Embeddings` → Vector representation of meaning
    - `Transformers` → Use self-attention for context understanding

---

## **Capabilities & Limitations**

✅ **Can Do:**

- Text generation, summarization, Q&A, code writing, translation

❌ **Limitations:**

- May hallucinate
- Biased by training data
- Doesn’t have real-world understanding

---

## **LangChain / LangGraph**

- Frameworks to build **LLM-powered applications**
- Connect LLMs with **tools, memory, and APIs**

**Core Components:**

- `LLMs` → Core language model
- `Prompt Templates` → Reusable input formats
- `Chains` → Sequential workflows
- `Agents` → Make dynamic decisions
- `Memory` → Retain conversation history
- `Tools` → APIs, functions, or databases

---

## **LangGraph (Advanced LangChain)**

- Graph-based orchestration of LLM workflows
- Allows **branching, looping, and multi-agent coordination**
- Used for **complex, dynamic AI systems**

---

## **AI Agents**

- **Definition:** LLMs + Tools + Memory + Logic
- **Purpose:** Perform tasks autonomously
- **Types:**
    - `Reactive Agents` → Respond based on input
    - `Proactive Agents` → Plan and execute multi-step tasks
- **Examples:**
    - Research Agent
    - Personal Assistant
    - Task Planner

---

## **Vector Databases (VectorDBs)**

- Store embeddings for **semantic search**
- Enable context-aware and memory-based AI
- Examples → `Pinecone`, `Weaviate`, `FAISS`, `ChromaDB`

**Functions:**

- Store embeddings
- Perform similarity search
- Retrieve relevant context for prompts

---

## **RAG (Retrieval-Augmented Generation)**

- Combine **LLMs + Vector Databases** for contextual output

**Steps:**

1. Convert user query → embedding
2. Search VectorDB → retrieve similar documents
3. Combine retrieved data → feed to LLM

**Use Cases:**

- Document Q&A
- Knowledge assistants
- Custom chatbots

---

## **Multi-Agent Systems**

- Multiple agents collaborating to complete tasks
- Each agent has a dedicated role

**Example:**

- `Planner Agent` → Defines workflow
- `Research Agent` → Gathers information
- `Writer Agent` → Generates final output

---

## **Building Generative AI Apps**

🧩 **Tech Stack:**

- **Frontend / UI:** `Streamlit`
- **Backend Logic:** `Python`
- **LLM Framework:** `LangChain` / `LangGraph`
- **Vector Database:** `Pinecone`, `ChromaDB`, or `FAISS`
- **Model APIs:** `Gemini`, `OpenAI`, `Mistral`, `HuggingFace`
